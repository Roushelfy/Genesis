# Automatic-radius DPR: qualified fast path, practical defaults and examples

**Active user goal, 2026-10-28.** Recover as much of the cheap volume DPR path as practical, make automatic-radius DPR the default, and deliver straightforward runnable examples. This is new implementation work following the completed [planar loading delivery](PLANAR_LOADING_RESULTS_20261027.md), not a request to rerun that campaign. Starting delivery is `73af7b0d1f83d5f4c78249e29471d18a4a2a18e3`; its measured engine is `6dedc79579ac0d113e4baac26eb538bcf51ca57d`.

## Intended result

Keep cheap Hertz sizing, finite-pressure DPR and the original prefactorized/response elastic recovery. Prefer a qualified low-cost path over globally paying for angle/q128. Start with edge/q16 and other inexpensive alternatives, measure their actual stress error, and use selective refinement or fallback where needed. If unchanged q16 cannot meet the application budget, retain the fastest validated alternative; a configuration that merely stops reporting a failure is not a winner.

Production preparation and runtime remain inside the Genesis rigid stress feature, entirely in Quadrants. Preserve fixed geometry/material, arbitrary changing/asymmetric convex/nonconvex contacts, both surface sides, normal force and friction with original application-point moments, max/full output, batching, reset/checkpoint and environment isolation. Keep volume FEM and shell as separate physical backends. Retain the qualified planar shell implementation and its performance gains. Do not reopen Atlas, stress enrichment, deformable-pad work or broad high-resolution convergence as prerequisites.

## Diagnose the failures before choosing tolerances

Freeze and replay the actual failing inputs, especially the historical heterogeneous volume frame221 and the newer policy tick606/env2/slot0. The latter reports pressure status3/errno128 while the elastic solve remains valid. That status is not a diagnosis: distinguish insufficient integration/support, sampled nonnegative-fit infeasibility, singular or poorly scaled systems, line-search/stagnation/iteration exhaustion, and a residual only slightly above threshold. Record the final residual, force and original-point moment errors, effective integration support, conditioning indicators, iteration/line-search behavior and stopping reason. Include nearby valid frames to check continuity.

The current pressure-fit stop is 1e-9 and final source-wrench checks are 1e-8. These are numerical safeguards, not direct stress-accuracy requirements. Historical angular q64 load errors of about1.0452e-6/1.0667e-6 only slightly exceeded a1e-6 comparison budget; that alone does not prove unusable stress, nor explain the edge/q16 status3 failure. Preserve both observations separately.

Evaluate a small, informative tolerance sweep, cheaper integration rules and stable/scaled fit formulations. It is explicitly authorized to revise the pressure-fit stopping rule and load-acceptance tolerances when actual complete-field/peak errors, conditioning and continuity justify the new application-oriented choice. Separate fit tolerance, final force/moment checks, integration-reference discrepancy, elastic residual and stress-error budgets; do not loosen them all together. Preserve the original strict configuration and failures as diagnostic/reference controls. Avoid weakening unrelated K residual, material-identity, nonnegativity, invalid-input or lifecycle checks to hide a pressure failure. A mathematically infeasible sampled support cannot be repaired by claiming a smaller solver residual.

Set and explain practical full-tensor/global-sampled-peak budgets before selecting a winner, using the intended damage-avoidance use rather than forcing near-machine-precision agreement in every intermediate quantity. Report absolute as well as normalized error when reference values are tiny, and distinguish global field error from loaded-region and remote-hotspot error. Any change from an older budget must be visible, with the same candidate also evaluated under the original budget. Reference accuracy and physical-model uncertainty remain explicit; same-discrete-model agreement does not certify a continuum contact maximum.

## Recover and optimize the fast path

Prioritize cheap edge/q16 or a comparable rule plus selective repair: improve patch resolution/conditioning, reuse exact moments or the recent radial-integration ideas where applicable, refine only affected faces/contacts, and compact failing environments if a complete-environment replay is required. Choose contact versus environment granularity from correctness and measured full-path cost. Correctly remove/replace provisional contributions; avoid dropped sources, duplicate loads or mixing partial failed fits into the accepted result. Keep source/material/support semantics intact.

Study a cheap error/admission trigger as well as solver failure: a low-order fit can converge while its integration or stress is inaccurate. Offline reference export is not an online estimator. Measure false accepts, fallback frequency/cost and continuous switching. Do not make every source run q128 merely to decide whether q16 was sufficient. High-order mode stays available for reference or uncommon repair. Reuse device-resident packing, original acceptance, batched response and full/max fusion, and profile the combined actual path before tuning its remaining bottlenecks.

First use low-resolution frozen contacts and nearby trajectories, then complete scripted and actual policy-inference Franka/hollow-egg histories with small and heterogeneous banks. Include boundary/seam contacts, release/recontact, nonconvex material controls and focused reset/checkpoint regressions. Keep the exact mechanical input fixed for accuracy comparisons; a changed stress observation can alter a live policy's later contacts. Separate numerical consistency from integration/stress approximation, and separate accuracy work from primary throughput timing.

Compare the qualified fast/adaptive volume route with unchanged edge/q16 diagnostics, angle/q128 reference, the current planar shell route and pure rigid. Measure both max and full at a small batch and useful large batches, with paired repeats and matching controller/precision/contact inputs. Report module and complete-scene rates, valid/attempted steps, iterations, refinement/fallback/rejection rates, memory and preparation cost; retain all failures. Report the source identity and actual routing of every advertised configuration. Policy inference is not training throughput. Deliver a clear speed/error/memory recommendation rather than an unbounded parameter campaign.

## Change the actual defaults

Make automatic-radius DPR the ordinary configuration: `contact_model="pressure"`, `load_transfer="patch"`, `radius_model="hertz"`, `pressure_profile="hertz"`. This applies to `RigidStressOptions`, `.dpr(...)`, the included Franka workload and its CLI/benchmark wrappers; remove hard-coded legacy overrides so omitted options actually follow the new default. It does not enable stress on bodies that did not request it.

Keep explicit manual radius and the legacy DPR pressure profile available for reproducibility. Keep `.scr(...)` an intentional alternative; test that it does not accidentally inherit incompatible Hertz/DPR-only behavior when shared defaults change. Do not silently change material constants, collision geometry or the volume-versus-shell physical backend. The backend remains explicitly selectable and volume remains the default unless a separate, justified decision is documented. Retain Q4 shell loading as the existing default; show the qualified planar configuration explicitly and avoid advertising its k8/cap32 initial settings as the recommended full-workflow recipe.

Select inexpensive qualified integration/repair defaults from the new evidence, rather than making globally expensive q128 mandatory. Update option descriptions, API documentation and all active entrypoints together. For the sharp Franka jaws, retain the explicit documented `box_edge_policy="planar"` surrogate in examples; do not silently apply it to every unsupported geometry or introduce soft pads. Unsupported geometry still needs an explicit policy/error. Document migration from the previous manual6mm defaults and how to reproduce old behavior.
